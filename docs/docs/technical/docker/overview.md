# Docker Overview

Canopy is fully containerized with Docker Compose and driven by a `Makefile`.
You do not run raw `docker compose` commands by hand — the Makefile picks the
right compose files and env for you.

## Compose files

| File                          | Role                                                        |
| ----------------------------- | ---------------------------------------------------------- |
| `docker-compose.yml`          | Base topology (production shape): all services + networks. |
| `docker-compose.override.yml` | Dev-only: publishes ports, hot-reload volumes, adds Mailpit.|

The Makefile selects them from `ENV`:

```makefile
ENV=prod → -f docker-compose.yml
ENV=dev  → -f docker-compose.yml -f docker-compose.override.yml
```

## Common commands

```bash
ENV=dev make build      # build images
ENV=dev make start      # docker compose up -d (with COMPOSE_PROFILES if set)
ENV=dev make stop       # docker compose down -v  (⚠ removes volumes)
make rebuild-restart    # stop → build → start
```

Database helpers (run against the `api` container):

```bash
make apply-init-db      # apply docker/postgis/init_db.sql (schemas + REVOKE)
make apply-migration    # alembic upgrade head
make seed               # dev seed data
make setup-db           # init-db + migrate + seed
make reset-db           # ⚠ destructive: down -v, wipe data, restart, migrate, seed
```

## Environment

All services read `.env` (see [Installation](../installation)). Key points:

- Secrets `PRIVATE_KEY` and `ALTCHA_HMAC_KEY` are generated by `make genpkey` /
  `make genaltchakey` (done automatically by `make create-app`).
- The API's `DATABASE_URL` / `POSTGRES_HOST` are overridden in
  `docker-compose.yml` to point at **PgBouncer** (`?prepare_threshold=0`).

## Networks

- `frontend` — public-facing (via Caddy): caddy, frontend, docs, maputnik.
- `backend` — `internal: true`: api, postgis, pgbouncer, martin, redis, maputnik.

See [Services](./services) for the per-service breakdown and
[Development](./development) for the dev workflow.
